# Submission Checklist

Use this checklist to ensure your submission exactly matches the challenge requirements.

## A) Repository Quality

- [ ] Code and notebook are pushed to git repo
- [ ] `.git` directory is preserved in the zip archive
- [ ] Commit history is clean and meaningful
- [ ] Root `README.md` is complete and accurate

## B) README Requirements

- [ ] Files/directories explained
- [ ] Setup/run instructions included
- [ ] Deployed app links included
- [ ] AI usage explicitly mentioned

## C) App Requirements

- [ ] Actual vs forecast shown in UI
- [ ] Start/end time controls available
- [ ] Forecast horizon configurable (0-48h)
- [ ] Forecast selection logic uses latest forecast created before `target - horizon`
- [ ] Missing forecast points are skipped
- [ ] Mobile and desktop views usable

## D) Analysis Requirements

- [ ] Notebook contains error characteristics analysis
- [ ] Mean, median, p99 or equivalent shown
- [ ] Horizon-based error comparison shown
- [ ] Time-of-day error analysis shown
- [ ] Wind reliability recommendation (MW) justified with evidence
- [ ] Assumptions and trade-offs documented

## E) Deployment Requirements

- [ ] Frontend deployed (Vercel/Heroku/similar)
- [ ] Backend deployed (Render/Railway/Heroku/similar)
- [ ] Frontend points to deployed backend API
- [ ] Links updated in `README.md`

## F) Packaging and Links

- [ ] Zip archive created from repo root including `.git`
- [ ] Zip uploaded to Google Drive
- [ ] Drive sharing set to accessible to all with link
- [ ] Link added to submission form and `README.md`

## G) Demo Video (<= 5 min)

- [ ] Unlisted YouTube video created
- [ ] Frontend demo shown
- [ ] Backend logic explained
- [ ] Analysis summary explained
- [ ] Link added to form and `README.md`

## H) Final Form Submission

- [ ] All mandatory fields filled
- [ ] Repo link added
- [ ] Drive zip link added
- [ ] YouTube link added
- [ ] Submitted successfully
